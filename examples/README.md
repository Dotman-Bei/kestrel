# Examples

Everything in this folder was **generated by an actual scan**, not written by hand.
Regenerate it after any change to the engine, the policies or the fixture graph:

```bash
python scripts/generate_examples.py
```

The run is against `fixtures/healthcare.json` — a DataHub-shaped graph with the same failure
modes the sample datapacks plant. The shapes are real; the instance is not, and every
generated report says so in its `warnings`.

| File | What it is |
|---|---|
| [`violation-document.md`](violation-document.md) | **Start here.** The incident document Kestrel writes *into DataHub* for the headline finding: the rule, the hop-by-hop path, the real SQL behind each hop, the owner, and the fix. |
| [`pii-reaches-bi.report.md`](pii-reaches-bi.report.md) | The human-readable scan report for the whole run. |
| [`scan-report.json`](scan-report.json) | The machine-readable report (`kestrel scan --json`). This is also what the web UI reads. |
| [`before-after/`](before-after/) | What the run changed in the catalog — tags and structured properties, per entity, before and after. |
| [`remediation-pr.md`](remediation-pr.md) | The pull request Kestrel drafts for a fixable finding. |
| [`owner-notification.md`](owner-notification.md) | The owner ping it drafts. |
| [`agent-compiled/`](agent-compiled/) | A policy the **agent wrote itself** from a plain-English rule, plus the violation it then found. |

## What the run found

Six violations across four policies, from 15 subjects and 18 lineage paths:

| Policy | Found | The interesting part |
|---|---|---|
| `pii-reaches-bi` | 3 | `patients.ssn` reaches the `patient_overview` dashboard through a **4-hop path**. Note that `stg_patients.ssn` — hop 1 — **is not tagged PII**: the tag stopped at the source while the data kept going. A per-entity test sees a clean column. |
| `certified-without-owner` | 1 | `patient_encounters` is Certified with no owner. `patient_360` is Certified *with* an owner and is not reported — the rule discriminates. |
| `certified-dashboard-without-owner` | 1 | Same rule, dashboards. |
| `stale-upstream-feeds-live` | 1 | `patient_360` is certified but depends on `lab_results`, tagged `Stale`, **2 hops upstream**. |

## What it deliberately did *not* find

`patients.email` also reaches a dashboard — but it is hashed at the first hop, so the policy's
`without_step` clause excuses the path, and the scan says so out loud:

```
patients.email: path suppressed -- passes through masking step 'stg_patients_masked.email_masked'
```

A rule that fires on everything is not a rule. That line is the evidence it discriminates.
